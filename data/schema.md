# ImpactIQ — FEA Dataset Schema

This is the CONTRACT between Person 1 (SOLIDWORKS) and Person 2 (AI/backend).
Any file that matches this schema — synthetic or real SOLIDWORKS export — is a
drop-in replacement. Nothing downstream needs to change.

## Axis convention (do not change mid-hackathon)
- `Fx` = longitudinal force (N)
- `Fy` = lateral force (N)
- `Fz` = vertical force (N)

## File: `fea_dataset.csv`

| column              | type  | units | description                                              |
|---------------------|-------|-------|----------------------------------------------------------|
| Fx                  | float | N     | applied longitudinal force                               |
| Fy                  | float | N     | applied lateral force                                    |
| Fz                  | float | N     | applied vertical force                                   |
| von_mises_stress_MPa| float | MPa   | max von Mises stress reported by the study               |
| max_displacement_mm | float | mm    | max resultant displacement reported by the study         |

## File: `material.json`

```json
{
  "material_name": "string, e.g. Al 7075-T6",
  "yield_strength_MPa": 000.0,
  "elastic_modulus_GPa": 00.0
}
```

Person 1: when your SOLIDWORKS runs are ready, export a CSV with exactly these
5 columns (any number of rows — even 8-12 well-chosen load cases is enough for
a hackathon regression). Drop it in as `data/fea_dataset.csv` and fill in
`data/material.json`. Person 2's training script (`model/train.py`) picks it
up automatically — no code changes needed. Until then, `data/fea_dataset.csv`
is synthetic, generated by `data/generate_synthetic_data.py`, so the rest of
the pipeline can be built and demoed today.
