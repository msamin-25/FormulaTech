# ImpactIQ — FEA Dataset Schema

This is the CONTRACT between Person 1 (SOLIDWORKS) and Person 2 (AI/backend).
Any file that matches this schema — synthetic or real SOLIDWORKS export — is a
drop-in replacement. Nothing downstream needs to change.

## Axis convention (do not change mid-hackathon)
- `Fx` = longitudinal force (N)
- `Fy` = lateral force (N)
- `Fz` = vertical force (N)

## File: `fea_dataset.csv`

| column              | type  | units | description                                              |
|---------------------|-------|-------|----------------------------------------------------------|
| Fx                  | float | N     | applied longitudinal force                               |
| Fy                  | float | N     | applied lateral force                                    |
| Fz                  | float | N     | applied vertical force                                   |
| von_mises_stress_MPa| float | MPa   | max von Mises stress reported by the study               |
| max_displacement_mm | float | mm    | max resultant displacement reported by the study         |

## File: `material.json`

```json
{
  "material_name": "string, e.g. Al 7075-T6",
  "yield_strength_MPa": 000.0,
  "elastic_modulus_GPa": 00.0
}
```

Person 1: when your SOLIDWORKS runs are ready, export a CSV with exactly these
5 columns (any number of rows — even 8-12 well-chosen load cases is enough for
a hackathon regression). Drop it in as `data/fea_dataset.csv` and fill in
`data/material.json`. Person 2's training script (`model/train.py`) picks it
up automatically — no code changes needed. Until then, `data/fea_dataset.csv`
is synthetic, generated by `data/generate_synthetic_data.py`, so the rest of
the pipeline can be built and demoed today.

## We do NOT need node coordinates / a GNN

The model maps ONE force vector per load case to the peak response
(`[Fx,Fy,Fz] -> [max stress, max displacement]`). It is not a Graph Neural
Network, so it needs **no per-node X/Y/Z coordinates** — skip the manual
"List Results -> Save As CSV" spatial export. From each study we only need the
single peak von Mises stress and peak displacement, plus the force you applied.

## Getting from a raw SOLIDWORKS export to this schema

If your VBA API export gives **per-node stress** (node index + stress value)
rather than one summary row per study, use the adapter — it reduces each study
to its max stress and joins it to the force you applied:

1. Fill in `data/load_cases.csv` (a template): one row per study with the
   applied `Fx,Fy,Fz` and the peak `max_displacement_mm` (read off the study
   result summary — a stress plot has no displacement).
2. Run one of:
   ```bash
   # MODE A — you already recorded peak stress in the manifest:
   python data/from_solidworks.py --manifest data/load_cases.csv

   # MODE B — peak stress comes from per-node export files (one CSV per study,
   # filename starting with the study name):
   python data/from_solidworks.py --manifest data/load_cases.csv \
       --nodes-dir data/solidworks_exports
   ```
   This writes a schema-correct `data/fea_dataset.csv`. Node stress in Pascals
   (values ~1e8) is auto-converted to MPa.
